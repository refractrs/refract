# Shaders

Run the desktop example first:

```sh
cargo run -p refract --features cli -- dev -p refract-shader --platform desktop
```

Run the same view and WGSL source in a browser:

```sh
cargo run -p refract --features cli -- dev -p refract-shader
```

Move the pointer to move the light. Pause the clock, change intensity, or mix in
an image. Uniform transitions continue to animate while the shader clock is
paused. The image is a small checkerboard generated by the example.

## Supply your own shader

`Shader::wgsl` accepts either embedded source or a runtime string. It parses and
validates the program with Naga, returning source diagnostics on error. Keep the
result in application state or a `LazyLock`; cloning it shares the program.

```rust
use refract::prelude::*;

let program = Shader::wgsl(include_str!("custom.wgsl"))?;
let drawing = shader(
    program
        .uniform("intensity", 0.8_f32)
        .uniform("tint", Color::BLUE)
        .fallback(Color::rgb(25, 35, 65)),
)
.width(400.0)
.height(240.0)
.radius(16.0)
.clipped()
.schedule(ShaderSchedule::Animation);
```

Define a `Uniforms` structure and a `shade` function in your WGSL file:

```wgsl
struct Uniforms {
    intensity: f32,
    tint: vec4<f32>,
}

fn shade(frame: ShaderFrame) -> vec4<f32> {
    let wave = 0.5 + 0.5 * sin(frame.uv.x * 12.0 + frame.time);
    return vec4<f32>(uniforms.tint.rgb * wave * uniforms.intensity, uniforms.tint.a);
}
```

Refract supplies `ShaderFrame`, the `uniforms` global, the image sampler, resource
bindings, and vertex/fragment entry points. Do not declare your own GPU bindings
or entry points. For programs without parameters, use a single unused f32 member
in `Uniforms`. The framework owns a fullscreen triangle covering the view.

| Frame field | Meaning |
| --- | --- |
| `position: vec2<f32>` | Local logical pixel coordinates, top-left origin |
| `size: vec2<f32>` | Content width and height in logical pixels |
| `uv: vec2<f32>` | Normalized position, top-left `(0, 0)` |
| `time: f32` | Visible scheduled time in seconds |

Return straight-alpha sRGB RGBA, with components in `[0, 1]`. Refract converts to
premultiplied output for browser compositing. Native Vello receives straight
alpha. A shader does not capture the surrounding DOM or other views.

Uniform members support `f32`, `vec2<f32>`, `vec3<f32>`, and `vec4<f32>`. Bind them
with f32 values, fixed f32 arrays, or `Color` (normalized RGBA). The declared WGSL
layout determines offsets and alignment; you never write padding bytes yourself.
Uniform storage is limited to 16 KiB. Unbound members are zero. Unknown names,
incompatible dimensions, and nonfinite values fail validation before the host
applies the update.

## Reactive parameters and animation

Use `shader_with` to read parameters at the shader mount rather than its parent:

```rust
let drawing = shader_with(move |inputs| {
    program.clone().uniform("intensity", inputs.read(&intensity))
})
.animatable_inputs()
.schedule(ShaderSchedule::Animation);
```

The closure returns a bound `Shader`. Its graph reads subscribe only this mount.
GPU frames use committed values without reevaluating view bodies or layout.
`.animatable_inputs()` interpolates bound scalar/vector components using existing
animation transactions. Keep bound names and vector dimensions stable during an
animation. Images and fallback colors snap to the new target.

Schedules are independent from parameter animation:

- `OnChange` is the default: render after inputs or dimensions change, with time zero.
- `Animation` requests frames and advances visible time.
- `Paused` retains the clock without requesting continuous frames.

Hidden surfaces pause their clock. Reduced motion suppresses continuous time,
following the existing canvas policy. macOS and the browser observe the system
preference; other native hosts do not yet bridge it. Explicit parameter
animations still follow their animation transactions.

## Image input

Bind one immutable RGBA8 image with `program.image(ShaderImage::rgba(w, h, bytes)?)`.
Clones share the pixel allocation. `sample_image(uv)` returns straight-alpha sRGB
using linear filtering and clamp-to-edge addressing. Without an image it returns
transparent black. Decode PNG/JPEG/WebP assets into RGBA8 before binding them;
this API does not perform network requests or image decoding while drawing.

Images must be nonempty, at most 8192 pixels on either axis, and contain exactly
`width * height * 4` bytes. Output textures also cap each dimension at 8192 or the
GPU limit, while preserving the view's logical coordinate system.

## Rendering and lifecycle

Native rendering uses the existing wgpu device and composites the shader texture
through Vello. The browser uses a WebGPU canvas inside the normal DOM view. Both
retain pipelines, uniform buffers, and image textures. Size changes recreate the
necessary surfaces; removing a view releases its resources. Browser exit
transitions capture a static bitmap before releasing the live GPU surface.

Give the view explicit dimensions or let its parent allocate them. It has no
intrinsic size. Padding and borders surround the content. Use `.clipped()` with
`.radius(...)` for rounded clipping. Events and accessibility metadata belong to
the containing view; shader pixels are not individual controls.

WebGPU requires a secure context (HTTPS or localhost) and a usable GPU adapter.
The fallback color appears during initialization, in prerendered HTML, or after
GPU failure. Failed browser surfaces stop requesting continuous frames. Browser
inspection exposes `data-refract-shader="pending|ready|unavailable"` and an error
attribute on failure. Recreating the view retries initialization; there is no
WebGL fallback. Shader compilation is runtime validation, not a Rust macro.

## Validation

```sh
cargo test -p refract-core -p refract-test
cargo test -p refract-native gpu_shader -- --ignored
cargo build -p refract-web --example shader_fixture --target wasm32-unknown-unknown
```

The GPU pixel test covers uniform updates, logical coordinates, image sampling,
alpha, and time at 1x and 2x scale. Browser fixtures in
`crates/web/tests/browser/shader.html` cover rendering, resize, retained identity,
exit snapshots, remounting, fallback, hydration, and disposal during setup. Serve
the fixture alongside wasm-bindgen's `shader_fixture.js` output; append
`?mode=fallback`, `?mode=hydrate`, or `?mode=dispose` for the alternate cases.
